# Как участвовать

Спасибо за помощь с кодом, заданиями и документацией. Это независимый русскоязычный учебный проект; он не связан с официальным банком экзамена Яндекса. Техническая карта исходников, команды, правила обновления банка и обслуживание графики собраны в [DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Перед изменениями

Проверьте существующие [Issues](https://github.com/ed-would/yandex-ai-studio-exam-lab/issues). Для крупного изменения сначала опишите задачу и ожидаемое поведение. Для небольшого исправления можно сразу открыть pull request. Соблюдайте [правила общения](CODE_OF_CONDUCT.md); об уязвимостях сообщайте по [SECURITY.md](SECURITY.md).

## Локальная работа

Нужны Git и Node.js 24 с npm; минимальная версия Node.js – 22.12. Сделайте fork, склонируйте его и создайте ветку для своей задачи. Из корня проекта:

```bash
npm ci
npm run dev
```

Для изолированного просмотра результатов есть `npm run dev:results`. Зависимости фиксируются в `package-lock.json`; сохраняйте его вместе с изменениями `package.json`. `npm ci` устанавливает pre-commit через Lefthook. Перед отправкой изменений выполните:

```bash
npm run check
```

Команда проверяет JavaScript, CSS, форматирование, контракт банка, тесты и production-сборку. `npm run lint:fix` исправляет доступные проблемы автоматически; просмотрите результат перед коммитом. Не коммитьте `node_modules`, `dist`, `.env`, токены и личные резервные копии.

## Изменение вопросов

Прочитайте [CONTENT_CONTRACT.md](docs/CONTENT_CONTRACT.md) и исследование соответствующего домена в `docs/research-domain-*.md`. Сохраняйте 180 заданий, три уровня, шесть доменов и распределение типов. Для каждого вопроса нужны однозначный ключ, объяснение, разбор вариантов и прямые ссылки на первичные источники.

При исправлении приложите ID вопроса, обоснование и ссылку на источник с датой проверки. Не копируйте официальные экзаменационные задания или материалы, на распространение которых у вас нет прав. Не меняйте стабильные ID без необходимости. При изменении смысла или ключей обновите `BANK_VERSION` в `src/data/meta.js` и опишите последствия для сохранений: автоматической миграции между банками сейчас нет.

Валидатор проверяет структуру; корректность фактов и ключей нужно проверить отдельно.

## Pull request

Опишите проблему, изменения и выполненные проверки. Для интерфейса приложите снимки нужных экранов в светлой и тёмной темах; для исправления логики добавьте подходящую регрессионную проверку. Избегайте несвязанных изменений и новых зависимостей без необходимости. Не загружайте реальные данные пользователей в тесты или снимки.

Новые зависимости и сторонние ресурсы должны иметь совместимую лицензию. Vite автоматически собирает лицензии включённых зависимостей в `dist/.vite/license.md`; лицензии отдельно поставляемых ресурсов, включая шрифты, сохраняйте рядом с ними. Локальный патч `braces` обновляйте по [vendor/braces/README.md](vendor/braces/README.md), сохраняя его проверки и provenance.

## Права на вклад

Отправляя авторский вклад, вы соглашаетесь распространять его по [MIT](LICENSE). Сторонние материалы сохраняют свои лицензии и уведомления. Отдельный CLA или обязательный sign-off не требуется. Авторство проекта и просьба о ссылке на первоисточник описаны в [README.md](README.md).
