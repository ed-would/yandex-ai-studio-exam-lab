# Аудит кода тренажёра

Проверка выполнена 10 октября 2026 года. Область: приложение Preact, чистая логика экзамена и рекомендаций, сохранения и импорт, HTML-разбор, обе темы, адаптивный интерфейс, изображения, зависимости и конфигурация сборки. Предшествующие изменения темы и интерактивных состояний сохранены.

## Исправления

| Область | Найденная проблема | Исправление |
| --- | --- | --- |
| Сохранения | Сравнение revision и запись localStorage могли одновременно пройти в двух вкладках | Одна короткая очередь Web Locks защищает проверку и запись. Вторая вкладка получает предупреждение до перезаписи данных. |
| Совместимость сохранений | API Web Locks может отсутствовать или быть запрещён | Практика и экспорт продолжают работать в памяти вкладки; запись в хранилище отключена и явно показано предупреждение. Ранее сохранённые данные не меняются. |
| Импорт | Подтверждение импорта могло затереть более свежий прогресс другой вкладки | Импорт и очистка проходят через общую проверку конфликтов. Обход revision разрешён только для явно подтверждённого восстановления повреждённого или несовместимого сохранения. |
| Revision | Предельный счётчик из копии мог переполниться и сделать следующее сохранение нечитаемым | Импорт сбрасывает локальный счётчик, обычная запись безопасно обрабатывает границу MAX_SAFE_INTEGER. |
| Валидация | Неизвестные поля попытки и ответа переносились в приложение | Входные данные приводятся к явной структуре, даты нормализуются, ответ проверяется повторно. Неизвестные поля удаляются без изменения входного объекта. |
| Быстрые действия | Изменения мультивыбора и сопоставления могли использовать устаревший черновик при ожидании lock | Функциональные обновления вычисляются из актуального состояния внутри очереди. Завершение и перезапуск проверяют идентификатор попытки. |
| События браузера | Очистка sessionStorage могла ошибочно блокировать сохранения или сбрасывать тему | Обработчики проверяют storageArea и реагируют только на нужное хранилище. |
| Производительность | Небольшие иллюстрации загружались в исходном разрешении | Адаптивные WebP и реальные размеры источников; разные sizes для хиро, карточек, прогресса, компактных глифов и подложек. |
| DRY | Форматтеры чисел и дат создавались повторно | Общие экземпляры Intl.NumberFormat и Intl.DateTimeFormat. |
| Результаты | Кнопка «Повторить ошибки» включала также пропущенные задания | При наличии пропусков подпись явно говорит «Повторить ошибки и пропуски». |
| Доступность | role="img" у графика скрывал семантику вложенных ссылок | График – группа, ссылки имеют самостоятельные доступные названия, декоративные полосы скрыты от скринридера. |
| Иконки | Значок seed отсутствовал и заменялся запасной звездой | Добавлен самостоятельный SVG-глиф. |
| CSS | Недоставало Safari-префикса размытия и запасной высоты для dvh | Добавлены -webkit-backdrop-filter и vh перед dvh. |
| Сборка и сеть | Dev/preview слушали все сетевые интерфейсы; target был es2022 | По умолчанию 127.0.0.1; сборка использует baseline-widely-available. Доступ из LAN включается отдельным явным аргументом. |

## Производительность

Замер – холодная загрузка главной в новом Chromium-контексте, экран 390 × 844, DPR 2, touch, системная тёмная тема, одинаковая область просмотра. Сравнивались тела ответов изображений, загруженных для этого экрана; это не Lighthouse score и не суммарный сетевой трафик сайта.

| Загруженные изображения | 3 117 347 байт | 1 133 289 байт |

Исходники не удалены. Варианты меньшего размера выбирает браузер под CSS-размер и плотность экрана; исходное разрешение остаётся запасным источником. WebP кодируется lossless. Для четырёх полноразмерных преобразований дополнительно подтверждено побайтовое совпадение декодированных RGBA-пикселей. Уменьшенные адаптивные варианты ресэмплируются отдельно и не заменяют оригинал.

Манифест покрывает 26 исходных изображений. Тест проверяет существование и размеры всех вариантов. Дополнительные файлы увеличивают размер архива проекта примерно на 15 МБ, но браузер загружает подходящий вариант, а не весь архив. Галереи и сохранённые исходники остаются доступны.

Production bundle: JavaScript 592,27 kB / gzip 130,96 kB; CSS 108,13 kB / gzip 20,73 kB. В JavaScript входит полный авторский банк 180 вопросов. Новые runtime-зависимости, кэш, state manager, polyfill-пакет и API-сервер не добавлены. После завершения конфетти активных анимаций не остаётся; reduced motion отключает эффект.

## Безопасность и зависимости

Импорт ограничен 10 МБ, проверяет формат и версию банка, состав вопросов, варианты, пары, даты и уникальность попыток. Сохранённый флаг correct не считается источником истины: результат выводится из ответа. Неизвестные поля не попадают в рабочее состояние. В текстовом интерфейсе применяется экранирование Preact, самостоятельный HTML-разбор экранирует вставляемые значения. Внешние ссылки с новым окном используют noopener noreferrer.

Сайт хранит прогресс локально и не добавляет внешние аналитические запросы. Данные в localStorage доступны скриптам того же origin; это учебные результаты, а не защищённое хранилище секретов. Серверная авторизация и серверная оценка не требуются для текущего продукта.

Полный `npm audit`, включая dev-зависимости, – **0 уязвимостей**. Цепочка `braces` → `micromatch` → Stylelint исправлена локальным MIT-патчем `braces@3.0.3-patch.2`. Для [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) на момент исправления ещё нет опубликованного upstream-релиза; используется код ограничений глубины из [PR #72](https://github.com/micromatch/braces/pull/72) на закреплённом commit, с двумя дополнительными исправлениями после ревью.

Парсер ограничивает совместную вложенность скобок до 100 уровней, обходы готового AST имеют тот же предел, а expand обнаруживает циклы parent. Infinity/NaN и завышенный maxDepth не отключают защиту. Сохранены родительский контекст escapeInvalid, обычные glob-выражения и проверки Stylelint; отладочный вывод удалён. Восемь регрессий проверяют реальное поведение, соответствие установленного кода исходникам, границы, циклы и CSS-линт. Нулевой audit сам по себе не заменяет эту проверку кода.

Исходники, лицензия, происхождение и порядок обновления находятся в [vendor/braces/README.md](../vendor/braces/README.md). Локальный tarball устанавливается воспроизводимо через dev-зависимость и npm overrides; чистый `npm ci` с lifecycle-скриптами и `npm ls` проходят. Это инструмент разработки, он не входит в браузерную сборку.

## DRY, YAGNI и SOLID

Подсчёт результата, проверки ответов, импорт и рекомендации остаются чистыми функциями в core. UI использует существующие компоненты вопросов, фильтров и оформления. Сохранения имеют одну точку записи, отображение изображений – общий механизм выбора источников. Тестовое хранилище передаётся отдельно; рабочий код не зависит от тестового окружения.

Не добавлены классы, фабрики, интерфейсы с единственной реализацией, дополнительная база данных или универсальная система событий. Полная переделка App ради формального следования SOLID не дала бы измеримого улучшения для этого небольшого приложения. Банк фиксирован и мал; создание поискового индекса или кэша без измеренной проблемы не требуется.

## Совместимость и пределы проверки

Target соответствует [документированному Baseline Vite](https://vite.dev/config/build-options.html#build-target): Chrome/Edge 111+, Firefox 114+, Safari/iOS 16.4+. WebP, SVG, обычные DOM-события и адаптивный CSS не требуют ОС-зависимого runtime. Для безопасного долговечного хранения [Web Locks требует secure context](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API): HTTPS или localhost; при недоступности действует описанный режим памяти.

Фактически доступный браузер в Playwright MCP – Chromium 144 на macOS. Проверены desktop и touch/mobile emulation. Реальные Firefox, Safari, Windows, Linux, Android и iOS в этой среде не запускались; их поведение нельзя объявлять подтверждённым испытаниями. Совместимость старых браузеров ниже указанного Baseline не заявляется. Экранный ридер и визуальный контраст поверх изображений не заменяются автоматической проверкой CSS.

## Независимая проверка и принятие

Два независимых read-only аудитора проверили безопасность и frontend на одном снимке исходников. После общей серии исправлений выполнена одна повторная волна: frontend – APPROVE; безопасность – APPROVE_WITH_NOTES с замечанием о fallback без Web Locks и известной dev-зависимости. Fallback затем исправлен root, подтверждён целевыми тестами, полной командой check и production-сценариями. Дополнительная независимая волна не проводилась.

Исправление braces и предупреждений выделено в отдельную ограниченную проверку. Независимый security-рецензент подтвердил реальное устранение переполнения стека, затем нашёл два дефекта upstream-патча: потерю родительского контекста stringify и отладочный вывод compile. Оба исправлены одним пакетом с регрессиями. Единственная повторная проверка этого пакета завершилась APPROVE; также подтверждены относительные пути готовой сборки. Бюджет и результаты прежнего полного аудита сохранены.

Все найденные локальные дефекты исправлены, включая уязвимость dev-инструмента. Реальные испытания других браузерных движков и ОС остаются за пределами доступной среды. Развёртывание и push в этом аудите не выполнялись.
