## 1. Содержание и контракт банка

Валидатор подтвердил:

- ровно **180** заданий: три уровня × шесть доменов × десять;
- распределение **4 single + 4 multi + 2 match** в каждой из 18 групп;
- **72** одиночных вопроса, **72** множественных, **36** сопоставлений;
- уникальные идентификаторы и нормализованные формулировки;
- русскоязычные обязательные текстовые поля;
- допустимые правильные варианты и полные взаимно однозначные сопоставления;
- объяснение каждого варианта и каждой пары, общий разбор и памятку;
- **50 уникальных прямых HTTPS-ссылок** в полях источников;
- наличие вопросов с одним и пятью правильными вариантами мультивыбора в каждом домене. В итоговом банке представлены все количества от одного до пяти.

Содержательная проверка опиралась на исследовательские журналы шести доменов и повторную редакторскую сверку ключей, условий и объяснений. Устранены неоднозначности в конфиденциальности и трансграничной обработке, различии трудозатрат и длительности, составе плагинов, подписках, хранении и доступах. Расчётные кейсы используют явно заданные учебные числа. Уровень 3 содержит задачи с несколькими ограничениями.

Валидатор выявляет нарушения структуры, но не доказывает истинность каждого утверждения. Обоснования и границы доступа к первоисточникам доступны в [SOURCE_REVIEW.md](SOURCE_REVIEW.md) и отдельных журналах доменов. Банк не проверялся на совпадение с закрытыми официальными экзаменационными вопросами.

## 2. Логика и сохранения

В `tests/core.test.mjs` прошло **72 проверки, включая вложенные случаи**. Они охватывают:

- строгое оценивание всех типов без частичных баллов;
- лишний и пропущенный вариант, дубликаты и неизвестные идентификаторы;
- запрет повторного использования правого элемента, замену и удаление пары;
- фиксацию первого проверенного ответа и неизменность завершённой попытки;
- черновики, неполные пары, текущую позицию и закладки;
- досрочное завершение и ноль за непроверенные задания;
- основной процент, показатели доменов и отдельный взвешенный ориентир;
- независимость уровней, режимов полного теста и работы над ошибками;
- сохранение истории и защиту новой попытки от завершения устаревшей;
- лучшие и последние результаты, отделение тренировок ошибок от полных экзаменов;
- JSON-копии, ограничения размера, несовместимые версии и повреждённые структуры;
- пересчёт оценки по ответам при импорте, без доверия флагу `correct`;
- запрет молчаливой перезаписи повреждённого сохранения;
- отказы localStorage, нехватку места и конфликты ревизий между вкладками;
- отдельные ключи хранения для разных путей сайта;
- полноту HTML-разбора и экранирование текста и атрибутов.

Во время проверки была обнаружена и исправлена ошибка завершения устаревшей попытки: теперь она не может удалить активную попытку с другим идентификатором или ключом. Добавлены проверки обоих случаев.

В `tests/dom.test.mjs` прошло **13 сценариев** в Node.js с happy-dom. Они взаимодействуют с реальными компонентами Preact через DOM-события.

| Сценарий | Что подтверждено |

| Мультивыбор | Принимаются все пять вариантов; ключ не раскрывается до проверки |

Сценарий с эталонными ответами проверяет прохождение компонентов и расчёт результата. Он не заменяет содержательную экспертизу вопросов.

## 4. Проверка комплекта для публикации

Дополнительно проверено:

- все ссылки `src`/`href` на ресурсы в `dist/index.html` относительные и ведут к существующим файлам;
- в `dist` находятся локальная иконка, `.nojekyll` и уведомления о лицензиях;
- CSS и прикладной JavaScript не содержат обращений к удалённым API, загрузки внешних шрифтов или CDN;
- YAML-файл workflow читается, реагирует на `main` и ручной запуск, выполняет `npm ci`, затем `npm run check` и публикует `dist`;
- используемые GitHub Actions закреплены полными SHA из [официального примера Vite](https://vite.dev/guide/static-deploy.html#github-pages), прочитанного в дату подготовки;
- относительный `base` согласован с [документацией Vite](https://vite.dev/guide/build.html#relative-base); маршруты приложения находятся после `#`;
- README описывает фактические команды, кнопки, подсчёт и поведение сохранений.

## 5. Границы выполненной проверки

**Реальный браузерный и визуальный прогон не выполнялся.** В среде не был доступен предусмотренный навыком Sites инструмент `control-browser`; правила этого рабочего процесса не позволяли подменять его другим браузерным инструментом или запускать preview-сервер. Поэтому не заявляются проверка пиксельного отображения, скриншотов, реальных сенсорных устройств, Chrome, Firefox, Safari или работы экранного диктора.

В коде предусмотрены адаптивная сетка, перенос длинного текста, клавиатурные элементы управления, заметный фокус, текстовые статусы правильности, объявления изменений сопоставления и поддержка `prefers-reduced-motion`. Их наличие проверено по исходникам и указанным DOM-сценариям; отдельная сертификация доступности не проводилась.

В реальный GitHub-репозиторий приложение не публиковалось: запросом предусмотрен готовый ZIP для самостоятельного размещения. Работоспособность workflow в конкретном аккаунте, разрешения организации и итоговый публичный адрес не проверены. Исходники и готовая статическая сборка подготовлены для этого способа публикации.

Приложение не использует авторизацию в Яндексе или вызовы модели. Материалы по внешним ссылкам могут позднее измениться либо снова потребовать CAPTCHA. Проверенные условия доступа и открытые замены перечислены в обзоре исследования.

## Воспроизведение

В корне распакованного проекта:

```bash
npm ci
npm run check
```

Для самостоятельного просмотра выполните `npm run dev` либо `npm run preview` после сборки. Для GitHub Pages следуйте разделу README и приложенному workflow.
