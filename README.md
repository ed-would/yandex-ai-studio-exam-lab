Основа содержания — программа в редакции **4 октября 2026 года**; открытые источники проверены **9 октября 2026 года**. ## Быстрый запуск

Понадобится **Node.js 24** с npm. Проект допускает Node.js от 22.12; проверенная среда указана в [отчёте о проверке](docs/TEST_REPORT.md).

Склонируйте репозиторий и установите зависимости:

```bash
git clone https://github.com/ed-would/yandex-ai-studio-exam-lab.git
cd yandex-ai-studio-exam-lab
npm ci
```

Если вы скачали ZIP, распакуйте его и откройте терминал в папке с `package.json`, затем выполните `npm ci`.

Запустите приложение:

```bash
npm run dev
```

Откройте адрес из терминала, обычно **http://127.0.0.1:5173**. Если порт занят, Vite покажет другой адрес. Остановка сервера — `Ctrl+C`. Серверы разработки и preview доступны только на этом компьютере. Для осознанного тестирования в своей локальной сети используйте `npm run dev -- --host 0.0.0.0`; подключение по обычному HTTP работает без долговечного сохранения прогресса, если браузер не предоставляет Web Locks.

`npm ci` использует приложенный `package-lock.json`. Первой установке нужен доступ к npm. После установки для прохождения тестов не нужны ключи API, аккаунты Яндекса, внешние шрифты, CDN или обращения к модели. Ссылки на учебные статьи открываются отдельно и требуют доступа к интернету.

### Быстрый просмотр результатов

```bash
npm run dev:results
```

Откройте **http://127.0.0.1:4178**. В верхней панели выберите тест и сценарий результата либо нажимайте «Предыдущий» / «Следующий»: доступны все три уровня, границы 60/80/95%, идеальный результат, все неверные ответы, пустая и досрочная попытки, работа над ошибками. Можно проверять обе темы, разборы, фильтры, историю и экспорт. «Открыть результат» возвращает к выбранному макету после перехода на другую страницу.

Макеты живут только в памяти отдельного режима. Настоящие сохранения не читаются и не изменяются. Смена сценария и перезагрузка восстанавливают макеты; выбранный результат остаётся в адресе. Панель подключается только в этом dev-режиме и не входит в обычную production-сборку. Если порт занят, остановите прежний сервер этого режима либо явно задайте другой порт: `npm run dev:results -- --port 4179`.

Для настоящего прохождения запускайте `npm run dev` и используйте один и тот же адрес: `localhost`, `127.0.0.1`, разные порты и пути имеют отдельные сохранения. Изменение CSS или компонентов само по себе не очищает прогресс. Если постоянное сохранение недоступно, приложение пробует сохранить текущий прогресс в этой вкладке: он переживёт её обновление, но перед закрытием вкладки нужно скачать копию. Если недоступно и хранилище вкладки, предупреждение сообщает о работе только в памяти.

## Что внутри

Крупные заголовки набраны шрифтом [Unbounded](https://github.com/googlefonts/unbounded). Кириллица и латиница подключены локально из `public/fonts`; лицензия SIL Open Font License 1.1 лежит рядом с файлами шрифта.

Кнопка солнца и луны в шапке переключает светлую и тёмную темы. При первом открытии используется тема системы, затем выбор сохраняется отдельно от результатов тестов и синхронизируется между вкладками. Переключение сохраняет текущий вопрос и черновики; анимация учитывает настройку уменьшения движения. Ночная тема сохраняет лаймовые, мятные и сиреневые акценты уровней. Фоны обеих тем находятся в `public/images/artwork`, архивные исходники и промпты — в `docs/design-lab`. Скачанный HTML-разбор сохраняет выбранную тему, печать остаётся светлой.

| Уровень | Подход | Вопросов | Оформление |
| --- | --- | ---: | --- |
| 1. Базовый | Основные понятия ИИ и простые рабочие ситуации | 60 | Шалфейный и лаймовый, объёмная розетка |
| 2. Продвинутый | Выбор подхода, диагностика ошибок и работа с ограничениями | 60 | Мятный и бирюзовый, орбитальная композиция |

| 2 | Практическое применение в работе | 10 | 18% |

| 4 | Внедрение и ценность для бизнеса | 10 | 16% |

## Как проходить тест

- Выберите уровень и начните попытку. Карта вопросов позволяет переходить между заданиями, а закладки помогают отметить то, к чему хочется вернуться. Синяя рамка обозначает текущий вопрос на любом уровне; зелёная — верный ответ, красная — ошибку, жёлтая — выбранный, но ещё не проверенный черновик.
- В вопросе с одним ответом выберите один вариант. В мультивыборе отметьте весь набор правильных утверждений.
- В сопоставлении нажмите элемент одной колонки, затем элемент другой. Можно начинать с любой стороны. Чтобы изменить связь, выберите новую пару; занятый элемент освободится от прежней связи. Крестик удаляет одну связь, «Сбросить связи» — все связи текущего задания. Повторный выбор той же пары также разрывает её.
- До нажатия **«Проверить»** ответ остаётся редактируемым черновиком. Кнопка проверки сопоставления станет доступна после заполнения всех пар.
- После проверки появляются результат, правильный ответ, объяснение и короткая памятка. Подробный разбор рассматривает каждый вариант или пару. Внизу находятся ссылки для дополнительного чтения.
- **Проверенный ответ зафиксирован.** Изменить результат текущего задания, вернувшись назад или перезагрузив страницу, нельзя. Для новой оценки нужна новая попытка.
- Можно выйти на главную и продолжить позже. Текущее место, черновики, проверенные ответы, связи и закладки сохраняются.
- Досрочное завершение требует подтверждения. Непроверенные задания, включая заполненные черновики, получают ноль баллов.

По умолчанию тренажёр работает без ограничения времени. Перед новой попыткой включите «Таймер для новых попыток» над карточками уровней или кнопками повторения на экране результата. Режим применяется к полному тесту и работе над ошибками; у продолженной попытки остаётся прежний режим. Если текущая попытка начата без таймера, вернитесь к тестам, включите переключатель и выберите «Начать заново»: включить отсчёт посреди уже начатой попытки нельзя.

С таймером на каждый вопрос даётся **72 секунды (1:12)**: 60 минут × 60 / 50 вопросов. Для наших 60 вопросов это до 72 минут на ответы. Таймер закреплён справа над вопросом, последние 10 секунд выделены красным и подписью «Время истекает». Ответ засчитывается по нажатию «Проверить». Когда срок истёк, черновик удаляется, вопрос получает 0 баллов и пометку «Время вышло», а тест переходит к следующему вопросу без ответа. После последнего такого вопроса результат открывается автоматически. Разбор и правильные варианты остаются доступны.

Время посещённого вопроса продолжает идти после перехода по карте, выхода из теста или обновления страницы. Возврат не выдаёт новые 72 секунды; новый отсчёт начинается только при первом открытии другого вопроса. Ещё не открытые вопросы не теряют время. Это учебная тренировка темпа с фиксированными наборами, а не точная симуляция всех правил настоящего экзамена.

## Как считается результат

За полностью правильное задание — **1 балл**, за ошибку или пропуск — **0**. Для мультивыбора должен совпасть весь набор выбранных вариантов; для сопоставления — все пары. Частичных баллов нет.

**Основной процент = число правильных ответов / число заданий × 100**, с округлением до одного десятичного знака. Например, 47 правильных из 60 дают **78,3%**. Все 60 заданий полного теста имеют одинаковый вес.

Отдельно, в раскрываемом пояснении результата, показан ориентир с весами доменов из программы: сумма долей правильных ответов по доменам, умноженных на 14, 18, 12, 16, 12 и 28%. Он не заменяет основной балл и не является прогнозом официальной оценки.

Цель **80%** выбрана для самостоятельной тренировки. Это **не официальный проходной балл**.

После завершения доступны:

- общий результат и показатели по каждому домену;
- полный разбор всех заданий с вашими и правильными ответами;
- фильтры по ошибкам, пропускам, правильным ответам, закладкам и доменам;
- отдельная тренировка ошибочных и пропущенных заданий;
- пересдача текущего уровня и переход к следующему;
- скачивание самостоятельного HTML-разбора со всеми ответами, объяснениями и ссылками.

В разделе **«Прогресс»** сохраняются отдельные результаты каждого уровня, лучшие и последние баллы, история и динамика последних попыток. Работа над ошибками имеет собственную историю и не повышает лучший балл полного экзамена.

## Сохранения и перенос

Данные находятся в `localStorage` этого браузера. Каждый ученик видит собственный прогресс. Сервер, база данных и учётная запись не требуются.

В разделе «Прогресс» можно:

- скачать резервную копию JSON;
- восстановить её на другом устройстве или в другом браузере;
- очистить один выбранный уровень;
- очистить все результаты, включая незавершённые попытки.

Очистка и восстановление требуют подтверждения в интерфейсе. Импорт заменяет текущие сохранения; перед этим удобно скачать свою копию. Приложение проверяет формат, версию банка, состав ответов и пересчитывает результат, вместо того чтобы доверять сохранённой цифре.

Сохранения относятся к сочетанию браузера, адреса сайта и пути проекта. `localhost`, GitHub Pages и другой репозиторий — разные хранилища. Для переноса используйте копию. Очистка данных браузера удаляет прогресс; в приватном режиме долговечность хранения зависит от браузера.

Если браузер запретил запись или закончилось место, приложение сообщит об этом и позволит скачать текущие данные. Повреждённые сохранения не перезаписываются молча. Если прогресс изменился в другой вкладке, потребуется обновить данные перед продолжением.

В поддерживаемых браузерах запись защищена общим Web Lock для вкладок одного сайта. Для долговечного сохранения используйте HTTPS или localhost. При старой или повреждённой записи, отсутствии Web Locks либо ошибке записи исходные данные устройства не перезаписываются: текущий прогресс отдельно сохраняется через `sessionStorage` в этой вкладке, если браузер разрешает доступ. Он переживает обновление страницы и правки кода в dev-режиме; перед закрытием вкладки скачайте копию. Если недоступно и это хранилище, остаётся только память открытой страницы. В обоих случаях приложение показывает предупреждение. Успешное постоянное сохранение, очистка или импорт удаляют временную копию; изменение исходных данных в другой вкладке делает её недействительной.

## Публикация на GitHub Pages

Готовый workflow находится в **`.github/workflows/pages.yml`**. Он устанавливает зависимости, проверяет банк, запускает тесты, собирает проект и публикует `dist`.

1. Создайте репозиторий на GitHub и поместите **содержимое** папки `ai-exam-lab` в его корень. `package.json` и `.github` должны находиться в корне репозитория. Не добавляйте `node_modules`.
2. В репозитории выберите **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Отправьте изменения в ветку **`main`**. Либо откройте **Actions → Publish to GitHub Pages → Run workflow** и запустите публикацию вручную.
4. Дождитесь успешного завершения workflow. Адрес появится в разделе Pages и в результате задания публикации.

Если основная ветка называется иначе, измените `branches: [main]` в workflow. Если GitHub Actions отключены настройками репозитория или организации, их нужно разрешить.

В Vite задано `base: './'`, а навигация использует hash-маршруты вида `#/exam/1`. Поэтому приложение может находиться и в корне домена, и в подпапке репозитория; задавать его имя в коде не нужно. Пользователям тренажёра не требуется авторизация GitHub.

Архив исходников с GitHub не содержит `dist` и `node_modules`. Готовую сборку создаёт `npm run build` или workflow GitHub Pages; эти папки исключены из Git через `.gitignore`.

Официальные технические ориентиры: [развёртывание Vite на GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages), [относительный base](https://vite.dev/guide/build.html#relative-base). Публикация в конкретный GitHub-репозиторий не входит в выполненную локальную проверку.

### Проверки перед коммитом

При `npm ci` скрипт `postinstall` устанавливает Lefthook и проверяет наличие его `pre-commit`. Ошибка установки в Git-репозитории завершает команду с ненулевым кодом. Если lifecycle-скрипты отключены, выполните `npm run hooks:install` вручную. В распакованном архиве без `.git` установка хука пропускается. Если установленный хук не найдёт исполняемый файл Lefthook, он блокирует коммит.

Перед каждым коммитом запускается `npm run check`: Oxlint для JavaScript в `src/`, `scripts/`, `tests/` и корневых конфигурациях, Stylelint для `src/**/*.css` и `public/**/*.css`, Oxfmt, контракт 180 вопросов, тесты и production-сборка. Ошибка блокирует коммит. Проверки читают рабочую папку целиком, включая изменения, ещё не добавленные в индекс; они не исправляют и не добавляют файлы в коммит автоматически.

Набор Oxlint, Oxfmt и Stylelint взят из решения о линтах в `ai-b2b-marketplace` и адаптирован к Preact + htm + обычному CSS. ESLint, Vue/Nuxt, TypeScript и серверные проверки не нужны. Форматтер сохраняет содержимое htm-шаблонов и порядок импортов. Он пропускает изображения, историю генераций, сторонние лицензии, документы и JSON-файлы банка; банк отдельно проверяется валидатором. Тот же `npm run check` выполняется в GitHub Actions перед публикацией. Just не требуется: команды проекта доступны через npm.

После `npm run build` можно разместить содержимое `dist` на любом сервере статических файлов. Для просмотра готовой сборки без npm, если установлен Python 3:

```bash
python3 -m http.server 8080 --directory dist
```

В Windows с установленным Python Launcher используйте `py -3 -m http.server 8080 --directory dist`. Затем откройте http://localhost:8080. Используйте HTTP-сервер, а не двойной щелчок по `dist/index.html`: браузерные модули рассчитаны на загрузку через HTTP. `vite preview` предназначен для локальной проверки, а публичную версию обслуживает статический хостинг.

Стек — **Preact + htm + Vite**, обычный JavaScript и CSS. SVG-композиции и иконки находятся в исходниках; удалённые картинки и шрифты не загружаются. `happy-dom` применяется только в тестах и не входит в браузерную сборку.

Оформление использует цветовые отсылки к [Yandex AI Studio](https://aistudio.yandex.ru/) и собственные геометрические композиции. Знак Yandex AI Studio обозначает платформу экзамена; отдельный логотип тренажёра создан для проекта. Заголовки используют локальный Unbounded с лицензией OFL.

Правила оформления собраны в [дизайн-системе](DESIGN.md): `#004C59` зарезервирован для логотипа Yandex AI Studio; отдельные палитры уровней обозначают соответствующие тесты. Сиреневый также оформляет учебный контекст — материалы, шесть областей знаний и блок шагов обучения. Общие ссылки, активное меню, прогресс и primary-кнопки в светлой теме используют экспертный фиолетовый `#6841AB` (кнопки с белым текстом). В тёмной теме сохраняется составной градиент из светлых оттенков всех трёх уровней с тёмным текстом кнопок. Примитивы и общие цвета задаются токенами `--level-*` и `--ui-*` в `public/theme-controls.css`; подвал, включая его кнопку, сохраняет отдельную серо-зелёную палитру обеих тем через `--footer-*`.

## Аудит и оптимизация

[Отчёт аудита кода](docs/CODE_AUDIT.md) содержит исправления, измерения загрузки изображений, проверки production-сборки и границы подтверждённой совместимости. Текущий комплект проверок: автоматические тесты, Oxlint, Oxfmt, Stylelint, валидатор 180 вопросов и Vite build.

Последний зафиксированный аудит зависимостей описан в [отчёте аудита](docs/CODE_AUDIT.md); для актуальной проверки выполните `npm audit`, включая dev-зависимости. Для Stylelint используется локальный security-патч `braces`; исходники, лицензия и порядок обновления — в [vendor/braces/README.md](vendor/braces/README.md). Патч нужно заменить после выхода совместимого исправленного upstream-релиза и повторной проверки. Установка точных зависимостей — через `npm ci`.

Компоненты выбирают подходящий размер изображения через `picture`, `srcset` и `sizes`. В `public/images` находятся только используемые файлы: знаки в `brand`, остальные креативы в `artwork`. Адаптивные варианты имеют суффикс `-optimized`, например `hero-ribbon-expanded-768-optimized.webp`; одинаковые изображения обеих тем используют один файл. Максимальный вариант сохраняет исходные ширину и высоту; WebP сжимается без потерь и используется только если весит меньше исходника. Если полноразмерный WebP тяжелее, сайт использует исходный JPEG, PNG или WebP. Список вариантов — в `src/data/image-variants.json`. Production-сборка включает только файлы из списка вариантов и необходимые ресурсы интерфейса, включая SVG платформы, favicon, шрифты и их лицензию. Неиспользуемые исходники, старые варианты, промпты и галерея концептов хранятся в `docs/design-lab` и в `dist` не копируются. Для обновления после изменения исходных картинок запустите `python3 scripts/optimize-images.py` в Python с установленным Pillow. Это необязательная команда обслуживания: Node.js, сборка и сайт не зависят от Python.

Входы оптимизатора перечислены в `scripts/optimize-images.py`. Используемые полноразмерные файлы берутся из `public/images/brand` и `public/images/artwork`. Исходники, которые заменены более лёгким вариантом, берутся из `docs/design-lab/logos` и `docs/design-lab/artwork` по тому же имени. После изменения нужного исходника запустите оптимизатор; адаптивные файлы записываются в `public/images`, а одинаковые варианты не дублируются. Для архивного концепта сначала экспортируйте обновлённое изображение по имени соответствующего входа оптимизатора, сохранив нужные размеры.

## Обновление вопросов

Сначала прочитайте [контракт банка](docs/CONTENT_CONTRACT.md) и исследование нужного домена. Каждый вопрос должен иметь однозначный ключ, объяснения и прямые ссылки на первичные материалы. Формулировки более сложного уровня должны проверять дополнительные условия и рассуждение.

После изменений выполните `npm run check`. Валидатор проверяет структуру, количество и допустимые ключи; содержательную корректность должен проверить редактор. При изменении смысла вопросов или правильных ответов обновите `BANK_VERSION` и продумайте миграцию истории. Текущая версия защищает несовместимые сохранения, но автоматической миграции между разными банками не реализует.

Материалы и продукты могут меняться. В банке не закреплены реальные тарифы или быстро меняющиеся числовые лимиты. Числа в экономических задачах — явно заданные учебные условия.
