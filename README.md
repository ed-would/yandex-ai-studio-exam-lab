# Практикум ИИ

Русскоязычный тренажёр для самостоятельной подготовки к экзамену **«Основы работы с ИИ» на платформе Yandex AI Studio** по [опубликованной программе Яндекса](https://ai-basic-competencies.website.yandexcloud.net/). Внутри — три тренировочных теста по 60 авторских вопросов с объяснениями и разборами.

**180 авторских вопросов · 3 тренировочных теста · 6 доменов · без регистрации и сервера приложений.**

Это независимый учебный проект. Он не создан и не одобрен Яндексом, не содержит официального банка экзамена и не выдаёт сертификаты. Основа содержания — программа в редакции **4 октября 2026 года**; открытые источники проверены **9 октября 2026 года**. Подробности исследования, ограничения доступа и ссылки — в [обзоре источников](docs/SOURCE_REVIEW.md).

## Быстрый запуск

Понадобится **Node.js 24** с npm. Проект допускает Node.js от 22.12; проверенная среда указана в [отчёте о проверке](docs/TEST_REPORT.md).

1. Распакуйте архив.
2. Откройте терминал в папке `ai-exam-lab`, рядом с `package.json`.
3. Установите зависимости одной командой:

```bash
npm ci
```

4. Запустите приложение:

```bash
npm run dev
```

Откройте адрес из терминала, обычно **http://localhost:5173**. Если порт занят, Vite покажет другой адрес. Остановка сервера — `Ctrl+C`.

`npm ci` использует приложенный `package-lock.json`. Первой установке нужен доступ к npm. После установки для прохождения тестов не нужны ключи API, аккаунты Яндекса, внешние шрифты, CDN или обращения к модели. Ссылки на учебные статьи открываются отдельно и требуют доступа к интернету.

## Что внутри

| Уровень | Подход | Вопросов | Оформление |
| --- | --- | ---: | --- |
| 1. Основа | Понятия, различия и простые рабочие ситуации | 60 | Шалфейный и лаймовый, объёмная розетка |
| 2. Практика | Выбор метода, диагностика ошибок и работа с ограничениями | 60 | Персиковый и терракотовый, орбитальная композиция |

На каждом уровне представлены все шесть доменов, **по 10 заданий** на домен. Наборы фиксированы: пересдача запускает тот же набор, а следующий уровень предлагает другие задания. Любой уровень доступен сразу; проходить их по порядку необязательно.

| Домен | Название | Заданий на уровень | Приблизительный вес в официальной программе |
| ---: | --- | ---: | ---: |
| 1 | Основы ИИ и генеративного ИИ | 10 | 14% |
| 2 | Практическое применение в работе | 10 | 18% |
| 3 | Ответственный ИИ | 10 | 12% |
| 4 | Внедрение и ценность для бизнеса | 10 | 16% |
| 5 | ИИ-агенты и инструменты агентской платформы | 10 | 12% |
| 6 | Алиса AI Про для бизнеса: коннекторы, навыки и автоматизация | 10 | 28% |

В каждом домене каждого уровня — **4 вопроса с одним ответом, 4 с мультивыбором и 2 на соответствие**. В целом: 72 + 72 + 36 = 180. Мультивыбор всегда предлагает пять вариантов; правильными могут быть от одного до всех пяти.

## Как проходить тест

- Выберите уровень и начните попытку. Карта вопросов позволяет переходить между заданиями, а закладки помогают отметить то, к чему хочется вернуться.
- В вопросе с одним ответом выберите один вариант. В мультивыборе отметьте весь набор правильных утверждений.
- В сопоставлении нажмите элемент одной колонки, затем элемент другой. Можно начинать с любой стороны. Чтобы изменить связь, выберите новую пару; занятый элемент освободится от прежней связи. Крестик удаляет одну связь, «Сбросить связи» — все связи текущего задания. Повторный выбор той же пары также разрывает её.
- До нажатия **«Проверить»** ответ остаётся редактируемым черновиком. Кнопка проверки сопоставления станет доступна после заполнения всех пар.
- После проверки появляются результат, правильный ответ, объяснение и короткая памятка. Подробный разбор рассматривает каждый вариант или пару. Внизу находятся ссылки для дополнительного чтения.
- **Проверенный ответ зафиксирован.** Изменить результат текущего задания, вернувшись назад или перезагрузив страницу, нельзя. Для новой оценки нужна новая попытка.
- Можно выйти на главную и продолжить позже. Текущее место, черновики, проверенные ответы, связи и закладки сохраняются.
- Досрочное завершение требует подтверждения. Непроверенные задания, включая заполненные черновики, получают ноль баллов.

Тренажёр не ограничивает время: его цель — практика с немедленным разбором. Это учебный режим с фиксированными наборами, а не точная симуляция всех правил настоящего экзамена.

## Как считается результат

За полностью правильное задание — **1 балл**, за ошибку или пропуск — **0**. Для мультивыбора должен совпасть весь набор выбранных вариантов; для сопоставления — все пары. Частичных баллов нет.

**Основной процент = число правильных ответов / число заданий × 100**, с округлением до одного десятичного знака. Например, 47 правильных из 60 дают **78,3%**. Все 60 заданий полного теста имеют одинаковый вес.

Отдельно, в раскрываемом пояснении результата, показан ориентир с весами доменов из программы: сумма долей правильных ответов по доменам, умноженных на 14, 18, 12, 16, 12 и 28%. Он не заменяет основной балл и не является прогнозом официальной оценки.

Цель **80%** выбрана для самостоятельной тренировки. Это **не официальный проходной балл**.

После завершения доступны:

- общий результат и показатели по каждому домену;
- полный разбор всех заданий с вашими и правильными ответами;
- фильтры по ошибкам, пропускам, правильным ответам, закладкам и доменам;
- отдельная тренировка ошибочных и пропущенных заданий;
- пересдача текущего уровня и переход к следующему;
- скачивание самостоятельного HTML-разбора со всеми ответами, объяснениями и ссылками.

В разделе **«Прогресс»** сохраняются отдельные результаты каждого уровня, лучшие и последние баллы, история и динамика последних попыток. Работа над ошибками имеет собственную историю и не повышает лучший балл полного экзамена.

## Сохранения и перенос

Данные находятся в `localStorage` этого браузера. Каждый ученик видит собственный прогресс. Сервер, база данных и учётная запись не требуются.

В разделе «Прогресс» можно:

- скачать резервную копию JSON;
- восстановить её на другом устройстве или в другом браузере;
- очистить один выбранный уровень;
- очистить все результаты, включая незавершённые попытки.

Очистка и восстановление требуют подтверждения в интерфейсе. Импорт заменяет текущие сохранения; перед этим удобно скачать свою копию. Приложение проверяет формат, версию банка, состав ответов и пересчитывает результат, вместо того чтобы доверять сохранённой цифре.

Сохранения относятся к сочетанию браузера, адреса сайта и пути проекта. `localhost`, GitHub Pages и другой репозиторий — разные хранилища. Для переноса используйте копию. Очистка данных браузера удаляет прогресс; в приватном режиме долговечность хранения зависит от браузера.

Если браузер запретил запись или закончилось место, приложение сообщит об этом и позволит скачать текущие данные. Повреждённые сохранения не перезаписываются молча. Если прогресс изменился в другой вкладке, потребуется обновить данные перед продолжением.

## Публикация на GitHub Pages

Готовый workflow находится в **`.github/workflows/pages.yml`**. Он устанавливает зависимости, проверяет банк, запускает тесты, собирает проект и публикует `dist`.

1. Создайте репозиторий на GitHub и поместите **содержимое** папки `ai-exam-lab` в его корень. `package.json` и `.github` должны находиться в корне репозитория. Не добавляйте `node_modules`.
2. В репозитории выберите **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Отправьте изменения в ветку **`main`**. Либо откройте **Actions → Publish to GitHub Pages → Run workflow** и запустите публикацию вручную.
4. Дождитесь успешного завершения workflow. Адрес появится в разделе Pages и в результате задания публикации.

Если основная ветка называется иначе, измените `branches: [main]` в workflow. Если GitHub Actions отключены настройками репозитория или организации, их нужно разрешить.

В Vite задано `base: './'`, а навигация использует hash-маршруты вида `#/exam/1`. Поэтому приложение может находиться и в корне домена, и в подпапке репозитория; задавать его имя в коде не нужно. Пользователям тренажёра не требуется авторизация GitHub.

Папка `dist` уже включена в ZIP. Для GitHub Actions коммитить её необязательно: workflow создаёт свежую сборку из исходников. `.gitignore` исключает `dist` и `node_modules` из обычного коммита.

Официальные технические ориентиры: [развёртывание Vite на GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages), [относительный base](https://vite.dev/guide/build.html#relative-base). Публикация в конкретный GitHub-репозиторий не входит в выполненную локальную проверку.

## Сборка и другие команды

| Команда | Назначение |
| --- | --- |
| `npm ci` | Установка точных зависимостей из lock-файла |
| `npm run dev` | Сервер разработки, обычно порт 5173 |
| `npm run validate` | Проверка структуры и полноты банка |
| `npm test` | Тесты логики и взаимодействий в DOM |
| `npm run check` | Проверка банка, все тесты и production-сборка |
| `npm run build` | Проверка банка и production-сборка в `dist` |
| `npm run preview` | Локальный просмотр `dist`, обычно порт 4173 |

После `npm run build` можно разместить содержимое `dist` на любом сервере статических файлов. Для просмотра готовой сборки без npm, если установлен Python 3:

```bash
python3 -m http.server 8080 --directory dist
```

В Windows с установленным Python Launcher используйте `py -3 -m http.server 8080 --directory dist`. Затем откройте http://localhost:8080. Используйте HTTP-сервер, а не двойной щелчок по `dist/index.html`: браузерные модули рассчитаны на загрузку через HTTP. `vite preview` предназначен для локальной проверки, а публичную версию обслуживает статический хостинг.

Оформление использует цветовые отсылки к [Yandex AI Studio](https://aistudio.yandex.ru/) и собственные геометрические композиции. Логотипы и фирменные шрифтовые файлы Яндекса не включены.

## Обновление вопросов

Сначала прочитайте [контракт банка](docs/CONTENT_CONTRACT.md) и исследование нужного домена. Каждый вопрос должен иметь однозначный ключ, объяснения и прямые ссылки на первичные материалы. Формулировки более сложного уровня должны проверять дополнительные условия и рассуждение.

После изменений выполните `npm run check`. Валидатор проверяет структуру, количество и допустимые ключи; содержательную корректность должен проверить редактор. При изменении смысла вопросов или правильных ответов обновите `BANK_VERSION` и продумайте миграцию истории. Текущая версия защищает несовместимые сохранения, но автоматической миграции между разными банками не реализует.

Материалы и продукты могут меняться. В банке не закреплены реальные тарифы или быстро меняющиеся числовые лимиты. Числа в экономических задачах — явно заданные учебные условия.
